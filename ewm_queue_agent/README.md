# EWM queue monitoring

This read-only agent retrieves `MsgQueueSet` from `ZEWM_MSG_QUEUE_MON_SRV` and shows SAP's error and suggested checks. Suggestions are hypotheses, not confirmed root causes. Resolve issues and reprocess queues in SAP under your normal procedures.

The agent uses the existing S/4 connection configuration: `S4_DESTINATION_NAME` and its BTP Destination/Connectivity bindings, or `S4_BASE_URL`, `S4_USER`, and `S4_PASSWORD` for direct access. Ensure the configured destination points to the SAP system hosting the supplied service and that the service and user's authorizations are active. Optionally set `EWM_QUEUE_SERVICE_ROOT` to a different relative service path. No credentials are stored in this folder.

`GET /api/ewm/queues?warehouse=5070` filters on `Lgnum`, the filterable warehouse field in the supplied metadata. Results are limited to 1,000 records and the response flags truncation. Direction is derived from SAP's direction/type fields; if unavailable, users are directed to check SMQ1 or SMQ2.

Optional `date_from` and `date_to` ISO dates filter `Creadate`; a single date uses equality. Bounded ranges send `ge` at the start of the first day and `le` at 23:59:59 on the last day to SAP, as in the supplied example. At most 1,000 SAP records are returned; if more exist, results are marked truncated. The chat resolves relative dates using the browser's local calendar date. “Last N days” includes today, “last week” is the previous Monday through Sunday, and “last month” is the preceding calendar month. Other natural-language expressions use the configured LLM and may require clarification. The supplied metadata marks `Creadate` as non-filterable, despite the working examples; verify the deployed service's actual behavior.

Selecting a queue searches SAP Community for its error and, when discussion text is available, uses the configured LLM to summarize supported troubleshooting suggestions with links to the source discussions. Search results are cached in memory for one hour. The integration sends a sanitized error message to the public SAP Community service; numeric and alphanumeric tokens containing digits are removed, but the remaining text can still contain business-specific information. Message class and number and sanitized error text are also supplied to the configured LLM. Queue names, warehouse and delivery references are not intentionally sent. Outbound access to `community.sap.com` and the LLM provider is required. Community access can be blocked by bot protection; the UI reports the lookup as unavailable in that case. Discussions are community advice rather than verified SAP fixes.
