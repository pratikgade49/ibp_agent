# IBP knowledge retrieval pilot

The IBP Demand Planning agent searches approved UTF-8 Markdown files in
`rag/knowledge/ibp/` on each question. The directory starts empty. Add only material
approved for **all users of this application**, such as published planning SOPs.
Each file's name is its source label; use descriptive names and include the
document owner, version and review date in the document itself. Redeploy after
changing packaged documents on Cloud Foundry. Files in the application container
are not a durable store for uploads or edits.

The pilot performs local lexical matching over paragraphs and passes up to three
bounded excerpts to the IBP agent. It does not use embeddings, search PDFs, learn
from conversations, or provide document-level access control. Relevant wording
or SAP identifiers must overlap the question. No public upload endpoint is
provided. Keep private, customer-specific, unreviewed, or obsolete documents out
of this shared directory. For segregated content, implement authentication,
authorization and a durable document store before indexing it.

Set `IBP_KNOWLEDGE_DIR` to a directory of approved `.md` files to override the
default path. Only files directly in that directory are read. Files above 256 KB
and symbolic links are ignored. If no relevant excerpts are found, the agent
continues normally. Retrieved excerpts are untrusted context, and current SAP
values still come from live tools. Source references are generated by the LLM,
so review their accuracy as part of evaluation.

## Shared SharePoint folder (IBP pilot)

An optional background worker reads an explicitly configured Microsoft Graph
drive and folder into an in-memory shared snapshot. It scans on startup and
hourly by default; it does not modify SharePoint. Successful scans replace the
snapshot, including removals; a failed scan retains the last successful snapshot
until the next success or app restart. Restarting loses the snapshot until a
sync succeeds. Set these environment variables in Cloud Foundry or an ignored
local `.env` file, and restart the app:

* `SHAREPOINT_SYNC_ENABLED=true`
* `SHAREPOINT_TENANT_ID`, `SHAREPOINT_CLIENT_ID`, `SHAREPOINT_CLIENT_SECRET`
* `SHAREPOINT_DRIVE_ID`, `SHAREPOINT_FOLDER_ID` (Graph IDs for the shared folder)
* Optional: `SHAREPOINT_SYNC_INTERVAL_SECONDS` (default 3600, minimum 60)

The app identity needs Microsoft Graph read access to the folder and admin
consent as required by the tenant. The drive and folder IDs can be obtained by
an administrator with Graph Explorer or another authorized Graph client. The
sharing URL is not stored here: the Graph sharing-link resolution endpoint
documents broad write permissions, so use IDs rather than granting those just to
resolve the link. Assess least-privilege selected permissions and tenant support
with the Microsoft 365 administrator. Store credentials in a secret service or
private app environment, never in source control.

The first version reads `.md`, `.txt` (UTF-8), and `.docx`, including subfolders.
Other types, including PDF and Excel, are skipped. It scans at most 500 items,
limits supported files to 2 MB and extracted text to 200,000 characters per file.
An oversized supported file or failed read aborts the refresh to avoid publishing
an incomplete snapshot. Source filename, URL and modification date accompany
retrieved excerpts. This is an in-memory, single-instance pilot, not a durable
index; it does not automatically make knowledge available to the other agents.
